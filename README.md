# Лабораторная работа №2 — многопоточный анализ текста

Отдельный проект Java 21: генератор текстов и семь способов подсчёта частоты слов. Чтение UTF-8, нормализация регистра и пунктуации, проверка по независимому эталону, измерения, ускорение и эффективность.

## Запуск в NetBeans

1. **File → Open Project** → выберите папку `laba2`.
2. Нужна поддержка **Java with Ant** и JDK **21 или новее**. Java 8 для этой лабораторной не подходит. Maven и сторонние Java-библиотеки не нужны.
3. **Run Project (F6)** компилирует проект, при первом запуске создаёт корпус `generated-data/default`, затем запускает все варианты. Повторные запуски используют тот же корпус.
4. Прогресс и количество правильных запусков видны в **Output**. Новые таблицы сохраняются в `results/latest/`, исходные результаты в `results/small`, `medium`, `large` не перезаписываются.

По умолчанию F6 использует размеры генератора из задания: **128 файлов по 250 000 слов**, словарь 500 слов; потоки 1, 2, 4, 8, 16, 32, 64; 2 прогрева и 5 измерений. Это 32 миллиона слов и длительный полный эксперимент. Некоторые варианты намеренно некорректны — сообщения о несовпадениях для них ожидаемы.

Для короткого первого запуска до создания корпуса можно изменить в `build.xml`:

```xml
<property name="generator.args" value="${data.dir} 64 2000 500"/>
```

Для собственного эксперимента измените `run.args`, например:

```xml
<property name="run.args" value="--variant=long-adder --threads=1,2,4,8 --warmups=2 --runs=5"/>
```

При изменении объёма данных укажите **новый** `data.dir`: генератор отказывается перезаписывать непустую папку. Существующий корпус при F6 не изменяется.

## Уже выполненные эксперименты

| Корпус | Файлов | Слов в файле | Всего слов |
|---|---:|---:|---:|
| small | 64 | 500 | 32 000 |
| medium | 64 | 2 000 | 128 000 |
| large | 64 | 8 000 | 512 000 |

Для всех вариантов внутри одной серии использовались одни и те же файлы. Каждый вариант проверялся при 1, 2, 4, 8, 16, 32, 64 потоках; последовательный — только при 1. Во всех конфигурациях 2 прогрева и 5 измерений. Размеры выбраны меньше полного примера генератора, чтобы провести всю матрицу экспериментов на доступной машине.

См. **[выводы и графики](results/conclusions.md)**. В каждом каталоге результатов:

- `measurements.csv` — медиана, минимум, ускорение, эффективность и правильность;
- `samples.csv` — каждый прогрев и замер с числом несовпадающих слов;
- `timings.md` — удобная таблица;
- `time.png`, `speedup.png`, `efficiency.png` — графики корректных алгоритмов;
- `environment.txt` — JVM, ОС, логические процессоры, методика и SHA-256 корпуса;
- `generation.properties` — размеры и seed для повторного получения тех же файлов.

## Сборка и команды вне IDE

Все команды выполняются из папки `laba2`, с JDK 21+ в PATH.

При установленном Ant:

```text
ant test jar
ant run
ant -Ddata.dir=generated-data/custom "-Dgenerator.args=generated-data/custom 64 2000 500" generate
ant -Ddata.dir=generated-data/custom "-Drun.args=--threads=1,2,4,8 --out=results/custom" run
```

Без Ant, в PowerShell:

```powershell
New-Item -ItemType Directory -Force build/classes | Out-Null
$sources = (Get-ChildItem src/main/java -Recurse -Filter *.java).FullName
javac --release 21 -encoding UTF-8 -d build/classes $sources
java "-Dstdout.encoding=UTF-8" -cp build/classes ru.student.lab2.TestDataGenerator generated-data/custom 64 2000 500
java "-Dstdout.encoding=UTF-8" -cp build/classes ru.student.lab2.Main --data=generated-data/custom --out=results/custom
```

Генератор принимает позиционные параметры:

```text
каталог количество_файлов слов_в_файле размер_словаря [seed]
```

Без seed распределение каждый раз новое. С сохранённым seed и теми же размерами можно воспроизвести корпус в новой пустой папке.

После сборки JAR:

```text
java "-Dstdout.encoding=UTF-8" -jar dist/Lab2.jar --data=generated-data/custom --out=results/custom
```

Параметры анализатора:

| Параметр | Назначение |
|---|---|
| `--data=...` | Входной каталог с текстами и `expected-statistics.txt` |
| `--out=...` | Отдельный каталог результатов |
| `--variant=all` | Все варианты или одно имя из списка ниже |
| `--threads=1,2,4,8,16,32,64` | Количества потоков |
| `--warmups=2` | Прогревы перед замерами |
| `--runs=5` | Количество основных замеров |
| `--help` | Справка |

Даже при выборе одного параллельного варианта сначала измеряется последовательная база для вычисления ускорения.

## Реализации

| Имя | Способ обновления | Корректность при нескольких потоках |
|---|---|---|
| `sequential` | Один поток, HashMap | Да |
| `hashmap` | Общий HashMap, get + put | Не гарантируется |
| `synchronized-map` | synchronizedMap, get + put | Не гарантируется: два вызова не атомарны вместе |
| `concurrent-get-put` | ConcurrentHashMap, get + put | Не гарантируется по той же причине |
| `concurrent-merge` | ConcurrentHashMap.merge | Да |
| `long-adder` | ConcurrentHashMap + LongAdder | Да, итог читается после завершения работников |
| `local-maps` | Свой HashMap у каждого работника и объединение | Да |

Первые три общих словаря специально используются с составной операцией get/put для демонстрации гонок. Даже правильный отдельный запуск не доказывает безопасность алгоритма.

## Повторение всей серии и построение графиков

`tools/experiments.ps1` запускает три новых корпуса в отдельной папке серии:

```powershell
./tools/experiments.ps1 -Java 'C:/Program Files/Apache NetBeans/jdk/bin/java.exe' -Series new-series
```

Для графиков дополнительно нужен Python с Matplotlib. Для самого Java-анализатора Python не нужен:

```text
python -m pip install -r tools/requirements.txt
python tools/report.py --results results/new-series
```

По умолчанию `report.py` строит графики по сохранённым `results/small`, `medium`, `large`. Чтобы не смешивать результаты, используйте `--results` для новой серии. Перед перестроением убедитесь, что серия использует те же 2 прогрева и 5 замеров.
